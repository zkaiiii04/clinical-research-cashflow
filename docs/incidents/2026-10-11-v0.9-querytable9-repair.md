# Incident: v0.9_working opens with "Removed Part: /xl/queryTables/queryTable9.xml"

**Logged:** 11 October 2026 · **Status:** open, to be fixed in the next session
**Reported by:** user, opening the v0.9 package workbook from SharePoint in desktop Excel on a work PC

## Symptom

Excel opened `Clinical_Research_Cash_Flow_SharePoint_PQ_Ready_v0.9_working.xlsm` from the SharePoint folder `04 Outputs Repository/Project Tracking System`, said it had to make repairs, and logged this:

```
Removed Part: /xl/queryTables/queryTable9.xml part. (External data range)
```

## What queryTable9 is

`xl/queryTables/queryTable9.xml` (`ExternalData_3`, connection 9 "Query - qManpower_SelectedTest") links the manpower selected-test table to its Power Query query. The table is `xl/tables/table15.xml` on sheet 14.

- v0.8: table `qManpower_SelectedTest` on sheet `PQManpower_SelectedTest`.
- v0.9: renamed to table `tblManpowerSelectedTest` on sheet `PQ_Manpower_SelectedTest`, at the user's request in the build session.

## Root cause (preliminary, high confidence)

### 1. The hidden name for the external data range still points at the old sheet name (definite defect)

Every Power Query table has a hidden defined name that tells Excel which cells the query table fills. In `xl/workbook.xml`:

| | Defined name | Refers to | Sheet exists? |
|---|---|---|---|
| v0.8 | `ExternalData_3` (localSheetId 13) | `PQManpower_SelectedTest!$A$1:$R$13` | yes |
| v0.9 (build output and shipped file) | `ExternalData_3` (localSheetId 13) | `PQManpower_SelectedTest!$A$1:$R$13` | **no**: the sheet is now `PQ_Manpower_SelectedTest` |

`build/build_v09_working.py` renamed the sheet in `workbook.xml` (`<sheet name=…>`) and in `docProps/app.xml`, but **not inside the defined-name formulas**. `ExternalData_3` was left pointing at a sheet that no longer exists. Excel can't place query table `ExternalData_3`, treats `queryTable9.xml` as corrupt, and removes it.

Evidence: a fresh rebuild from v0.8 with the current script reproduces the dangling name. `PQManpower_SelectedTest` appears nowhere else in the package except the Power Query DataMashup.

### 2. Power Query's saved load target still names the old table (likely contributor)

The DataMashup metadata for `Section1/qManpower_SelectedTest` records `FillTarget = qManpower_SelectedTest` and `FillTargetNameCustomized = 1`. The build left the DataMashup byte-identical by design, so after the XML-only rename the query's load target names a table that no longer exists. When a table is renamed in the Excel UI, Excel keeps the defined name and `FillTarget` in step; renaming by editing XML does neither. Even with cause 1 fixed, this mismatch could cause the same repair, or a broken refresh.

### Why only queryTable9

It's the only table and sheet that was renamed. The other nine query tables kept their names, and Excel accepted them.

## Contributing factors

- **The shipped workbook isn't the verified build output.** The `.xlsm` inside `release/CashFlow_v0.9_package.zip` has `docProps/app.xml` Application = **"Excel iOS"**.
  - Every query table, table and sheet part was re-serialised with placeholder IDs (`{00000000-0016-…}`).
  - `vbaProject.bin` gained stub modules for the new sheets.
  - By comparison, the build script's own output reports "Microsoft Excel" and keeps all ten query-table parts byte-identical to v0.8.
  - So at some point the built file was opened and saved in Excel for iPhone/iPad before it was zipped. Excel mobile can't run Power Query or VBA. This doesn't explain queryTable9 (the defect is in the clean build too), but it means the shipped file was never the one that `verify_v09_working.py` checked.
- **The verifier had a blind spot.** `verify_v09_working.py` exempted the manpower table part from the byte-identical check ("except the manpower table rename"). It didn't check that defined names point at existing sheets, or that each query table's name matches its query's `FillTarget`. So it reported PASS on a broken file.

## Impact

- In the repaired copy, `tblManpowerSelectedTest` is a **plain table that no longer refreshes**: the link to `qManpower_SelectedTest` is gone. Load Project would fail on the manpower refresh, or show stale manpower data.
- v0.8 is unaffected. Source workbooks are unaffected. The query definitions (M code) are intact.
- **Don't use or save the repaired copy.** If AutoSave already wrote it back to SharePoint, that copy is to be replaced with a rebuilt file. Don't overwrite v0.8.

## Fix plan for the next session

1. **Recommended: drop the rename from the build.** Keep the v0.8 names (`qManpower_SelectedTest`, sheet `PQManpower_SelectedTest`). The defined name, `FillTarget` and query table then all agree, with zero Power Query drift. If the user still wants the new names, rename **inside desktop Excel** after install (Table Design → Table Name; right-click the sheet tab → Rename). Excel then updates `ExternalData_3` and the query metadata itself. Update the VBA, `compare_pq.py`, the grid model and the docs to match whichever names are kept.
2. Alternative (riskier, only if the user insists on scripted names): also rewrite `ExternalData_3` to the new sheet name, and patch the DataMashup metadata `FillTarget` → `tblManpowerSelectedTest`. That means re-encoding the DataMashup binary, which the project has so far kept byte-identical.
3. **Harden `verify_v09_working.py`:**
   - every defined name's sheet reference must exist;
   - every query table's `name` and its table's `name` must match the DataMashup `FillTarget` for its connection's query;
   - the shipped file's hash must equal the build output's hash.
4. **Rebuild from v0.8** and run the verifier. Repackage the zip from the **exact build output**, and record a SHA-256 in `README_FIRST.txt`.
5. **Tell the user:**
   - download on the work PC and open **only in desktop Excel for Windows**;
   - don't open it in Excel on a phone, tablet or the web before the macros are installed;
   - if Excel offers repairs, stop and report rather than saving.
6. Then resume UAT (`tests/UAT_test_script.md`).

## Prevention

- **Never rename sheets or tables that Power Query loads by editing XML.** Rename them in the Excel UI, or not at all.
- The verifier checks cross-part references (defined names, query-table ↔ table ↔ FillTarget), not just byte equality.
- Ship only files whose hash matches the build output.
