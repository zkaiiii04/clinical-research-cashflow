# Incident: the timeline cuts off at the SOA budget LOA end date, not the project end date

**Logged:** 11 October 2026 · **Status:** open. Fix in the next session (the user asked for it to be logged, not fixed now).
**Reported by:** the user, testing the rebuilt v0.9_working in desktop Excel on project **tDCS** (Main IO `TF24HIP134`). The workbook they uploaded has the v0.8 manpower names and loaded without a repair prompt, which is good evidence the queryTable9 fix works.

## Symptom

On the tDCS dashboard, the MP Projected Project Total is **54,725**, which matches `qManpower_SelectedTest`. But the two manpower lines' month and quarter columns add up to much less, and **26,975** sits on "Unmatched: manpower months outside project dates" (Project Total only). The timeline stops at **FY26/Q3 (Dec 2026)**, though the project runs to **30 Sep 2027**.

## Reconciliation (from the uploaded workbook)

| Source rows | Months | FTE | Rate | Amount | Where it shows |
|---|---|---|---|---|---|
| AHS (OT/PT), `DB_AHS_Nurse_Distrib`, AH12_JUL25 (AHS) | Aug 25 – Oct 26 (15) | 0.1 each | 7,433.33 | 11,150.00 | inside the grid |
| RA, `DB_RA_Distrib`, AH11_JUL25 (RA) | Oct 25 – Dec 26 (15) | 2.4 total | 6,916.67 | 16,600.00 | inside the grid |
| RA, same row | Jan 27 – Sep 27 (9) | 3.9 total | 6,916.67 | 26,975.00 | **Unmatched row, Project Total only** |
| **Total** | | | | **54,725.00** | MP Projected Project Total |

The Power Query side is correct: FTE × Monthly Rate matches row by row, every row is "Rate matched", and the totals agree. The dashboard is missing the months from Jan to Sep 2027.

## Root cause

The **timeline dates come from the wrong source.**

| Object | tDCS Project Start | tDCS Project End | Where the dates come from |
|---|---|---|---|
| `tblProjectIOCatalogue` / `tblSelectedProjectMapping` | 1 Jan 2025 | **31 Dec 2026** | `qProjectIOCatalogue`: min/max of **`LOA Start Date` / `LOA End Date` on the SOA budget lines** (`tblCollation_Budget`), grouped by project + IO + code |
| `qProjects_SelectedTest` | 1 Jan 2025 | **30 Sep 2027** | IREx project information: Project Start / Project End, the authoritative project dates |

- The approved spec (§10.1 step 5, §12) and the build use `tblSelectedProjectMapping` (Main IO = Yes) for the grid's months and for Main_Dashboard **C7/C8**:
  - `modTimeline.bas`: the date read and consistency check around lines 269–307 read `Project Start` / `Project End` from `tblSelectedProjectMapping`;
  - `build/build_v09_working.py` writes C7 = `INDEX(tblSelectedProjectMapping[Project Start], MATCH("Yes", tblSelectedProjectMapping[Main IO], 0))` and C8 the same for Project End.
- That was a design error in the spec, which Claude wrote. The SOA budget LOA dates haven't been updated for tDCS's extension, so the grid ends at Dec 2026.
- Manpower months after the grid's end follow the spec's out-of-range rule (§9): Unmatched row, Project Total only, with a note.
- The **31/12/26** the user saw in the manpower table is the AHS person's **Tag End (LOA end)**, not the project end. The RA row's LOA runs from 1 Jan 2025 to 30 Sep 2027.

## Impact

- Any project whose SOA budget LOA dates are earlier than its IREx project end loses the later months from the grid. Manpower amounts and **typed projections** for those months land on Unmatched rows (Project Total only), and the quarter and FY columns for those months don't exist.
- C7/C8 (Project Start/End on the dashboard) show the SOA LOA dates.
- The reverse case (SOA LOA later than the IREx end) would add months past the real project end.
- Totals in the Project Total column and the KPI cards are **not** wrong: Unmatched amounts are counted.

## Also raised: OT vs RA amounts look swapped (needs the user to check the source)

The user expected **OT ≈ 43,575** and **RA ≈ 11,150**, based on the budget lines OT 42,000 and RA 10,800. The manpower table has the reverse:
- **RA (Projected) = 43,575**, from the tDCS row on **`DB_RA_Distrib`** priced at AH11 RA;
- **AHS (OT/PT) = 11,150**, from the row on **`DB_AHS_Nurse_Distrib`**, 0.1 FTE at AH12_JUL25.

Power Query takes the staff group from **which sheet a row is on**, and the workbook never moves rows between groups. Either the tDCS rows sit on the wrong distribution sheets in IREx, or the labels were crossed when read.
- **Next session: ask the user to check the IREx source rows.** If the OT person really is on `DB_RA_Distrib`, that's a source-data fix, not a workbook change.
- If the OT person is moved to the AHS sheet, their amount changes too: they'd be priced at their AHS grade rather than AH11 RA.

## Fix plan (next session)

1. **VBA (`vba/modTimeline.bas`):**
   - Take Project Start/End from **`qProjects_SelectedTest`**: the row whose `IO Code Type` = "Main" and whose IO = F6.
   - Fall back to `tblSelectedProjectMapping` only when those are blank.
   - Keep the existing consistency checks.
   - Add a Load warning when the two disagree, e.g. "SOA budget LOA dates (1 Jan 2025 – 31 Dec 2026) differ from the project dates (1 Jan 2025 – 30 Sep 2027); the timeline uses the project dates."
2. **Build (`build/build_v09_working.py`):** repoint C7/C8 to `qProjects_SelectedTest`, e.g. `=IFERROR(INDEX(qProjects_SelectedTest[Project Start],MATCH("Main",qProjects_SelectedTest[IO Code Type],0)),"")`. Check the exact table name in the workbook; v0.8 calls it `qProjects_SelectedTest`.
3. **Grid model (`tests/grid_model.py`):** use the same date source, and add a test case built from this incident: tDCS-like data with a mapping end of Dec 2026 and a project end of Sep 2027. Expect 33 months (Jan 25 – Sep 27), no Unmatched manpower row, RA line total 43,575 across its months, and MP Projected = 54,725.
4. **Spec and docs:** update spec §10.1 step 5 and §12, `CLAUDE.md` (approved design), the technical specification §6 and the build log.
5. **Rebuild and verify:** rebuild from v0.8, run `verify_v09_working.py`, repackage `release/CashFlow_v0.9_package.zip` from the exact build output with a new SHA-256, and give the user the updated `modTimeline.bas`.
   - If the user has already installed the macros in their copy, they can instead re-import `modTimeline.bas` and fix C7/C8 by hand. Give them both options.
6. **Re-test with the user** on tDCS: grid to Sep 2027, no Unmatched manpower row, C7/C8 = 1 Jan 2025 / 30 Sep 2027. Then carry on with UAT.

## Prevention

- Project dates have **one authoritative source**: IREx project information (`qProjects_SelectedTest`). The catalogue/mapping dates are SOA budget LOA dates and must never drive the timeline.
- The grid model gets a regression case where the SOA LOA and project dates differ.
